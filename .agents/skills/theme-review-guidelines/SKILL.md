# テーマ品質レビュー基準 & レビュー観点ガイドライン (Theme Review Guidelines)

OBS Studio および Zed エディタ向けのテーマを作成・改修する際に、**「実機の意匠再現性」「作業用 UI としてのアクセシビリティ」「動的システムとの互換性」「インストーラー・ドキュメントの整合性」** を漏れなく検証するための包括的な品質レビュー観点・チェックリストです。

> [!NOTE]
> 各ハードウェアおよび各 OS 固有の具体的なカラーパレットやピクセル測定値は、`docs/designs/` 配下の各詳細設計書を参照して照合を行ってください。

---

## 1. コントラスト & アクセシビリティ観点 (WCAG 準拠)

実機特有のカラーを採用しつつ、長時間の配信やコーディング作業に耐えうる優れた可読性を確保します。

### (1) 明色・白背景における視認性保護
* [ ] **高明度アクセント色（水色・黄色・黄緑等）の文字使用禁止**:
  - 高明度・高彩度カラーは、白・薄灰色背景上でのコントラスト比が 1.5:1〜2.5:1 程度となり可読性が崩壊するため、文字色としての単体使用を禁止しているか。
  - **原則**: 高明度アクセントカラーは色面（枠線・アイコン・塗りボタン・進行バー）に限定しているか。
* [ ] **反転テキスト・濃色代替色の徹底**:
  - アクセント色塗りボタン上の文字色には、白ではなく同系統の**濃色（コントラスト比 4.5:1 以上、推奨 6.0:1 以上）** を採用しているか。
  - 白背景上でアクセントカラー系統の文字が必要な場合は、高コントラストな**濃色代替色（コントラスト比 4.5:1 以上）** を採用しているか。
  - 白/薄灰背景上の警告色（warning / ⚠️）には、明黄色ではなく**ディープアンバー（コントラスト比 4.5:1 以上）** を採用しているか。

### (2) 暗色・ダーク背景における視認性保護
* [ ] **未選択アイテムの同化防止**:
  - リスト項目（シーン・ソース・設定ダイアログ）の未選択時テキストが高コントラスト色（白または極淡色）になっているか。
  - OBS 設定ダイアログ等で、未選択アイコンが黒系フォールバック（`#000000`）にならず、ダーク背景用の白系アイコンが明示指定されているか。
* [ ] **ツールバーボタン（＋、ゴミ箱、上下矢印）の可視化**:
  - 無効状態（disabled）のボタンでも背景色と枠線が維持され、アイコンが完全に背景に溶けて消えていないか（`opacity: 0.6` 以上の確保）。

## 2. 実機メタファー & 色彩階層観点

単なる色替えではなく、実機ハードウェアのマテリアルと機能階層に即したマッピングを行います。

### (1) 成型パーツ色 vs 印字・ロゴ色の厳格分離
* [ ] **成型色ボタンの原則**:
  - 実機に存在しない成型色のボタンを作らない（例: ロゴ色をボタン樹脂全体のベタ塗りにしない）。
  - ボタン自体は実機成型色（プラスチック、ラバー、金属等）とし、印字・アイコン・枠線にロゴ/機能色を配しているか。

### (2) 詳細設計書に準拠した色彩・マテリアル配置
* [ ] **各テーマの個別設計書（`docs/designs/*.md`）準拠**:
  - 当該テーマの設計書で定義されたカラーパレット、階調モデル、マテリアル意匠に正確に準拠しているか。
  - 外枠ベゼルカバーと内部スクリーン表示領域の役割分担が維持されているか。
  - 多色ボタン機種では機能ごとの直感的な分散配置、2色系統機種では主副アクションの階層化がなされているか。

### (3) コントロールボタンの意味づけマッピング
* [ ] **主要アクションの役割分担**:
  - 配信（Stream）: 注目度の高いキーカラー
  - 録画（Record）: 対比となる主要アクセントカラー
  - 仮想カメラ・スタジオモード: サブアクセントカラーまたはベース枠線
* [ ] **アクティブ/トグル状態の相互対比**:
  - 録画中・配信中のトグル時に、相手方の色や発光ボーダーで直感的に状態識別できるか。

## 3. OBS Studio テーマ特有の技術観点

### (1) レイアウト安定性（リフロー防止 & 寸法完全対称）
* [ ] **コントロールボタン枠線の 2px 固定**:
  - `#streamButton`, `#recordButton`, `#virtualCamButton`, `#modeSwitch` 等のボタンは、**通常時・ホバー時・押下時・アクティブ時（`:checked`, `.state-active`）の全状態で `border: 2px solid ...;` を固定** しているか（太さ変更によるガタつき・リフロー防止）。
* [ ] **チェックボックス等のサブコントロール寸法固定**:
  - チェックボックス（`QCheckBox::indicator`）の ON/OFF 切り替え時に、外枠寸法の変化、二重枠の発生、テキストの文字切れが発生していないか。

### (2) OBS 外観密度 & フォントサイズスライダー連動
* [ ] **固定ピクセル（px）ハードコードの禁止**:
  - ボタン、タブ、リストアイテム、入力フォーム、ツールバー等に `padding: 7px 14px;` や `font-size: 11pt;` などの固定値を書いていないか。
  - 設定の「密度（クラシック・コンパクト・通常・快適）」およびフォントサイズスライダーに完全連動するよう、OBS 公式動的計算変数（`var(--padding_large)`, `var(--padding_wide)`, `var(--tab_padding_base)`, `var(--input_padding)` 等）を使用しているか。

### (3) 構文・変数健全性
* [ ] **中括弧整合性**: `{` と `}` の出現数が 100% 完全一致しているか。
* [ ] **未定義変数の排除**: `var(--xxx)` で参照している変数は、`@OBSThemeVars` または OBS ベーステーマ（`Yami` / `Yami.Light`）で定義されているか。

### (4) 音声ミキサー (VolumeMeter)
* [ ] **テーマ固有メーター色**:
  - テーマの世界観に合わせた正常域・注意域・警告域の発光色が適切に設定されているか。

## 4. Zed エディタテーマ特有の技術観点

### (1) GPUI レンダリング & 透明度のルール
* [ ] **`element.selected` の完全透明黒（`#00000000`）禁止**:
  - 通常バリアントで `element.selected` に `#00000000` を指定すると選択ハイライトが完全に透明になり、ツリービュー等で選択状態が判別できなくなるため、必ず末尾 2 桁アルファによる半透明カラーを指定しているか。
* [ ] **テキスト色の白飛び防止**:
  - 半透明選択オーバーレイの上に白文字・黒文字が載った際、背景色と同化しない明度差が維持されているか。

### (2) シンタックスハイライトの機能性
* [ ] **文法要素ごとの明確な色分離**:
  - `keyword`（キーワード）、`function`（関数）、`string`（文字列）、`number`（数値）、`type`（型）、`comment`（コメント）が直感的に色分けされているか。
* [ ] **4バリアントの同時提供**:
  - 1 つの JSON 内で `通常`, `Blurred`（半透明ブラー）, `Dark`, `Dark Blurred`（または Light / Light Blurred）の 4 構成が一貫して定義されているか。

### (3) エディタキャレット（カーソル）のプレイヤーマッピング (`players`)
* [ ] **点滅カーソル（キャレット）のキーカラー設定**:
  - `players` 配列の先頭（Player 1: 自身）の `cursor` に、テーマを象徴する鮮やかなキーカラーが定義されているか。
  - マルチカーソルや共同作業時の `players`（Player 2〜4）にも世界観に即したアクセントカラーが整然と割り当てられているか。

## 5. インストーラー & ドキュメント整合性観点

### (1) インストーラーの健全性
* [ ] **PowerShell スクリプトの UTF-8 with BOM 厳守**:
  - `obs-studio/install.ps1` および `zed/install.ps1` は、Windows PowerShell 5.1 での日本語文字化けを防ぐため **UTF-8 with BOM（`\xEF\xBB\xBF` が先頭に 1 つだけ）** で保存されているか。BOM 重複事故がないか。
* [ ] **全 OS インストーラーの対象ファイル網羅**:
  - PowerShell（`.ps1`）、シェルスクリプト（`.sh`）、バッチ（`.bat`）の全インストーラーで、新規追加・変更されたテーマファイルが 1 つの漏れもなくコピー対象リストおよび適用方法メッセージに記載されているか。

### (2) ドキュメントの完全同期
* [ ] **`README.md` バッジ & 一覧表**:
  - テーマ数バッジ（`themes-X`）が最新数に更新されているか。
  - 対応テーマ一覧表、ディレクトリ構成図に全ファイルが反映されているか。
* [ ] **個別設計書（`docs/designs/*.md`）の同期**:
  - 新規テーマの追加や仕様変更時に、対応する詳細設計書が最新の状態に更新されているか。

## 6. 自動検証コマンド (クイックリファレンス)

PR レビューやリリースコミット前に、以下のワンライナーで全自動検証を実行できます：

```powershell
# 1. OBS OVT 中括弧 & 未定義変数チェック
python -c "import glob, re; [print(f, 'Braces:', open(f, encoding='utf-8').read().count('{') == open(f, encoding='utf-8').read().count('}')) for f in glob.glob('obs-studio/themes/*.ovt')]"

# 2. Zed JSON 構文 & 不透明度チェック
python -c "import glob, json; [json.load(open(f, encoding='utf-8')) for f in glob.glob('zed/themes/*.json')]; print('All Zed JSON Valid!')"

# 3. PowerShell BOM チェック
python -c "for p in ['obs-studio/install.ps1', 'zed/install.ps1']: b=open(p,'rb').read(); assert b.startswith(b'\xef\xbb\xbf') and not b[3:].startswith(b'\xef\xbb\xbf'), f'{p} BOM invalid'; print(p, 'BOM OK')"
```
