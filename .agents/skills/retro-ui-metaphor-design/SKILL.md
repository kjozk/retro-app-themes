# レトロハードウェア & クラシック OS UI メタファー設計原則ガイド (Retro UI Metaphor Design)

実在のハードウェア（ゲーム機・AV機器・シンセサイザー等）やクラシック OS をモチーフにした UI テーマ（OBS Studio, Zed エディタ, VS Code 等）を制作する際、**「実機特有のリアリティ」** と **「現代の作業用 UI としての優れた可読性（WCAG AAA 準拠）」** を高次元で両立させるための設計思想・手法・汎用アーキテクチャ原則です。

> [!NOTE]
> 各ハードウェアおよび各 OS 固有の詳細カラーパレット、ピクセル測定値、および実装コードは、本原則ガイドではなく `docs/designs/` 配下の個別設計書に切り出されています（第10節のインデックスを参照）。

---

## 1. 成型パーツ色と印字・ロゴ色の厳格な分離 (Molding vs. Silk-print)

### 原則
**ボタンやキーパーツに「印字・ロゴ色」を使ってはならない。**
実機に存在しない成型色のボタン（例: 印字やロゴが鮮やかな色だからといってボタン樹脂そのものをその色にする等）を作ると、玩具のような安っぽさが生じ、コントラスト設計も破綻します。

- **ボタン・スイッチ・つまみ**: 実機成型色（プラスチック成型色、ラバー色、金属色）をマッピングする。
- **テキスト・アイコン・刻印**: シルク印刷されたテキスト印字色やロゴ色をマッピングする。
- **効果**: 「実機パーツの上に文字が刻印されている」リアリティと、極めて明快なコントラスト比（7.0:1 以上）が成立します。

## 2. ベゼルカバー（外枠）とスクリーン（画面）の階層構造原則 (Bezel vs. Screen Metaphor)

### 原則
ディスプレイ画面を持つ機器を模す場合、画面色と筐体色の境界を厳格に定義します。

1. **プレビュー外周・メイン領域（ベゼルカバー樹脂色）**:
   プレビュー画面の外周は、ディスプレイ画面そのものの色ではなく、画面を覆う「ベゼルカバー樹脂色（スレートグレーやフレーム色）」を当てます。
2. **画面メタファー領域（小型サブディスプレイ）**:
   ディスプレイ画面を模したカラー（反射型液晶、モノクロ液晶、CRTアンバー等）は、設定サイドバーやソースリスト、入力ボックスなどの「四角い情報表示コンテナ」に適用し、小型サブディスプレイとしての没入感を演出します。
3. **画面メタファー領域内への異物混入防止**:
   画面表示を模したコンテナ内部には、ボタン色などの外部パーツカラーを持ち込まず、スクリーンの階調（明ハイライト、暗ドット）や同系色の枠線で完結させます。

## 3. 実機画面からのパレット抽出・階調設計手法 (Display Palette Extraction)

レトロな反射型液晶や CRT ディスプレイを再現する際は、実機写真・実機プレイ映像のピクセルを解析し、以下の **5 段階階調モデル** を導出して適用します：

| 役割 | 階調レベル | 適用対象・UI の振る舞い |
| :--- | :--- | :--- |
| **ベース画面背景** | 未点灯・基底色 | リスト・テキスト入力欄・コンボボックスの通常背景 |
| **最暗ドット前景色** | 最暗・点灯色 | 通常テキスト、アイコン、確定枠線、目盛り |
| **ホバー時背景** | 中間明度（微点灯） | マウスホバー時のフィードバック背景・枠線 |
| **確定選択・フォーカス** | 最高明度（強調点灯） | 選択中のアイテム行・フォーカス枠。文字色は最暗色を維持してコントラストを保護 |
| **無効状態 (Disabled)** | 減退・不活性色 | 入力不可パーツの背景。文字色は沈んだトーンで視認可能に維持 |

### 入力フォーム群への完全同期
リストボックスだけでなく、テキスト入力欄（`QLineEdit`）、コンボボックス（`QComboBox`）、スピンボックス（`QSpinBox`）にも同一の画面階調パレット（通常・ホバー・フォーカス・選択・無効）を一貫して適用することで、画面全体の統一感とメタファーの説得力が完成します。

## 4. クラシック OS の立体ベベル（3D Bevel）幾何学 (3D Bevel Geometry)

クラシックデスクトップ OS は、左上からの光源を想定した **4 色の基本システムカラー（面色、ハイライト、シャドウ、ダークシャドウ）** による光と影の組み合わせで立体感を表現します。

```
光源 (左上) ───────> [ ハイライト (明) ] ─────────────────┐
                     │                                   │
                     │           ボタン表面 (面色)       │  シャドウ (暗)
                     │                                   │  ダークシャドウ (最暗)
                     └────────────────── [ 影 (右下) ] ──┘
```

### 凸ボタン（Raised）と 凹入力欄（Sunken）の立体ルール
- **凸ボタン（通常時）**:
  外側左上＝ハイライト、外側右下＝ダークシャドウ、内側右下＝シャドウ。
- **凸ボタン（押下時 / Pressed）**:
  光と影が反転し、ボタンが押し込まれたように見せる（外側左上＝ダークシャドウ、外側右下＝ハイライト）。同時に文字を 1px 右下にオフセットする。
- **凹入力欄（テキストボックス・リスト）**:
  常時へこんだ枠線（左上＝シャドウ、右下＝ハイライト）で、画面の向こう側に掘り込まれた情報領域を表現する。

## 5. 光彩・グラデーション・プラスチック質感の設計原則 (Glow & Skeuomorphic Gloss)

2000年代以降のスキューモーフィズム UI では、フラットなベベルから滑らかなプラスチック光沢へと移行しました。

1. **ソフトな立体グラデーション**:
   ボタン通常時は面の上部から下部にかけて微細な明度グラデーションを施し、球形・円柱形のプラスチック表面を模します。
2. **光彩ホバー（Glow）**:
   マウスホバー時に、単なる色変化ではなく周囲に発光が漏れ出すような多色光彩（Glow）をボーダーに付与します。
3. **現代ディスプレイ向け色温度調整**:
   実機の黄ばみや古ぼけたトーンをそのまま写し取ると、現代のディスプレイでは単に「汚れて見える」場合があります。清潔感のあるペールシルバーやクールトーンへ調色し、モチーフの記憶色を美しく再現します。

## 6. 地域別意匠（リージョンバリエーション）の機能的マッピング原則 (Regional Variation)

同一世代のハードウェアであっても、販売地域によって成型色やボタン配色、マテリアル意匠が根本的に異なる場合があります。

- **単なる色置換の禁止**: 単に色相を変えるのではなく、そのリージョン機が持つマテリアル特性（例: 日本版の暖色アイボリー＋金プレートに対し、北米版の無彩色グレー＋赤刻印など）の思想を理解して再構築します。
- **機能階層への対応**: 
  - 複数色ボタン（4色等）が存在する機種: 主要アクション（配信、録画、仮想カメラ、スタジオモード）へ均等かつ直感的にマッピング。
  - 2色系統（例: 凸ボタン濃色 × 凹ボタン淡色）の機種: 主要アクション（配信・録画）を濃色、副次的アクション（カメラ・設定）を淡色に階層化。

## 7. クリーン＆ミニマルデザインにおける低コントラスト色の補償原則 (Low-Contrast Compensation)

白や明灰色を基調とするクリーンデザインにおいて、明度・彩度の高いアクセントカラー（水色・黄色・蛍光色等）を扱う際は、可読性破綻を防止するための 3 原則を厳格に適用します：

1. **境界・背景としての限定使用**:
   低コントラスト色はボタン塗り、枠線（Border）、進行バーなどの「色面・境界」としてのみ使用し、白背景上の文字色には絶対に使用しない。
2. **反転文字色の高コントラスト化**:
   アクセント色の塗りの上に乗せる文字は白ではなく、同色系の極めて濃いトーン（濃紺・ダークスレート等）を採用し、コントラスト比 6.0:1 以上を確保する。
3. **文字色用代替色の設定**:
   白背景上でアクセントカラー系統のテキストを表示する必要がある場合は、実機の発光部や濃色パーツから抽出した「同系色の深みのあるダークカラー」を文字専用色として定義する。

## 8. フラットUIにおけるキャレット枠と選択インジケーターの階層分離原則 (Caret vs. Indicator)

ミニマルなフラット UI において、「操作フォーカス（キャレット）」と「選択状態（インジケーター）」が共存する画面（設定リスト等）では、視覚的衝突を防ぐためレイヤーを多層分離します：

```
[フォーカス時]
┌── キャレットハイライト外枠 (一番外側を全周 2px で均一に囲む) ──────┐
│  │ 選択インジケーター (外枠の内側に余白を空けて独立配置)           │
│  │                                                                 │
│  │   [アイコン]   項目テキスト                                     │
└────────────────────────────────────────────────────────────────────┘

[非フォーカス時]
┌── 外枠は非表示 (透明) ─────────────────────────────────────────────┐
│  │ 選択インジケーター (左端に単独で残り、選択中であることを明示)    │
│  │                                                                 │
│  │   [アイコン]   項目テキスト                                     │
└────────────────────────────────────────────────────────────────────┘
```

1. **最外層（キャレット枠）**: 4 辺均一な枠線を一番外側に配置。
2. **内層（インジケーター）**: 外枠と重ならないよう、左端に独立して配置。
3. **余白の明示（パディング）**: インジケーターと後続のアイコン・テキストの間に十分な余白を確保し、文字やアイコンの被りを完全排除する。

## 9. 状態変化におけるレイアウト固定（リフロー防止）とコントラスト保護 (Layout Stability)

1. **固定枠線幅によるリフロー防止**:
   通常時・ホバー時・アクティブ時・無効時でボーダー幅を変動（1px → 2px 等）させると、ボタンサイズや周囲のコントロールが揺れる「リフロー」が発生します。全状態でボーダー幅を固定（例: `2px solid`）し、色のみを変化させます。
2. **トグルボタンのベタ塗り回避**:
   選択状態のボタングループにおいて、アクセント色でベタ塗りすると白文字とのコントラスト比が低下します。「深みのある背景 ＋ アクセント枠線 ＋ 純白文字」等の構造を採用し、選択状態の明確な識別と 12:1 以上の可読性を両立させます。
