# テーマ開発におけるスキルと設計書の責務分離ルール

OBS Studio および Zed エディタ向けのテーマ開発において、スキルと設計書の責務境界を以下のように厳格に分離・維持しなければなりません。

## 1. スキル (`.agents/skills/`) の記述原則
- スキルには、**特定の機種・ハードウェア・OS・製品固有のカラーコードや意匠情報をハードコードしてはならない**。
- スキルに記述できるのは、以下のような普遍的・再利用可能な知見のみとする：
  - 機種非依存の抽象的デザイン原則（成型色と印字色の分離、ベゼルと画面の役割分担、立体ベベル幾何学など）
  - QSS / GPUI の技術的デバッグ手順、アンチパターン、パーサー回避策
  - リフロー防止やコントラスト基準（WCAG AAA）等の品質レビュー観点・自動検証スクリプト
  - テーマおよびインストーラーの実装・配布ワークフロー

## 2. 設計書 (`docs/designs/`) の記述原則
- 特定の機種・ハードウェア・OS・製品に関する個別具体的な知見は、すべて `docs/designs/` 配下の各設計書にて一元管理する：
  - 実機写真・実機プレイ映像からのサンプリングカラーコードおよび HEX 変数定義
  - 各機種固有のマテリアル意匠、成型パーツ構成、ロゴ・印字の配置仕様
  - 各テーマの OBS (`.ovt`) および Zed (`.json`) 向けトークンマッピング
- 新規テーマを追加する際は、スキルを変更するのではなく、`docs/designs/` 配下に新規設計書（例: `docs/designs/<model_name>.md`）を作成し、`docs/designs/README.md` に登録する。
